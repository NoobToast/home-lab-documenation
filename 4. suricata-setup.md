# Suricata IDS/IPS Setup Guide for pfSense

**Author:** Greg Diny

A step-by-step guide to installing and configuring Suricata on pfSense for intrusion detection and prevention. This guide assumes you have already completed the [pfSense installation](installing-pfsense.md) and [VLAN setup](vlan-setup-pfsense.md) guides.

---

## What is Suricata?

Suricata is an open-source network intrusion detection and prevention system (IDS/IPS). It monitors network traffic in real time using signature-based rules to detect and optionally block malicious activity — exploits, port scans, malware callbacks, and more.

It operates in two modes:

- **IDS mode (detection only):** Suricata alerts on suspicious traffic but does not block it. Good for getting started without disrupting your network.
- **IPS mode (inline prevention):** Suricata actively blocks matching traffic. More powerful but requires careful tuning to avoid false positives.

Suricata sits behind pfSense and pfBlockerNG in your defense stack, providing deep packet inspection that the other two layers don't do.

---

## Prerequisites

- pfSense 2.6+ installed and configured
- pfBlockerNG set up (recommended — the two complement each other)
- Basic familiarity with pfSense navigation

---

## Installation

1. Navigate to **System → Package Manager → Available Packages**
2. Search for `suricata`
3. Click **Install** and wait for it to complete
4. Navigate to **Services → Suricata** to confirm the package loaded

## Step 1: Global Settings

Navigate to **Services → Suricata → Global Settings**

This page controls which rule sets Suricata downloads and how frequently it updates them.

### Rule Sets

| Setting | Value | Notes |
|---------|-------|-------|
| Install ETOpen Emerging Threats rules | ✓ | Free, community-maintained ruleset. Good baseline coverage. |
| Install ETPro Emerging Threats rules | Leave unchecked | Paid subscription — more frequent updates and broader coverage than ETOpen. Worth it if you want maximum coverage. |
| Install Snort rules | ✓ | Requires a free Snort account. Register at snort.org to get an Oinkmaster code. |
| Snort Rules Filename | `snortrules-snapshot-29111.tar.gz` | Enter the filename only — do not include the URL. Check snort.org for the current snapshot filename. |
| Snort Oinkmaster Code | (your code) | Obtain from your snort.org account dashboard after registering. |
| Install Snort GPLv2 Community rules | ✓ | Free Talos-certified rules distributed without a subscriber license. Updated daily. |
| Install Feodo Tracker Botnet C2 IP rules | ✓ | Tracks Dridex and Emotet/Heodo botnet C&C servers. |
| Install ABUSE.ch SSL Blacklist rules | ✓ | SSL certificate fingerprints of known malicious certs. |
| Hide Deprecated Rules Categories | Leave unchecked | Check this if the GUI becomes cluttered with old rule categories. |
| Download Extra Rules | Leave unchecked | Only needed if you have a custom rules archive. |

> **ETOpen vs. ETPro:** ETOpen is free and sufficient for most home lab setups. ETPro requires a paid Proofpoint subscription but includes all ETOpen rules plus significantly more coverage and faster updates. If you run a business network, ETPro is worth considering.

### Rules Update Settings

| Setting | Value | Notes |
|---------|-------|-------|
| Update Interval | 1 DAY | Daily updates are a good balance. Never disables auto-updates entirely. |
| Update Start Time | `00:00` | Runs at midnight. A random minute offset is added automatically to reduce load on rule servers. |
| Live Rule Swap on Update | ✓ | Performs a live reload of new rules without a full Suricata restart. Leave enabled. |
| GeoLite2 DB Update | Leave unchecked | Only needed if you want Suricata's own GeoIP functionality. If you're already using MaxMind through pfBlockerNG, this is redundant. |

### General Settings

| Setting | Value | Notes |
|---------|-------|-------|
| Remove Blocked Hosts Interval | NEVER | Only applies to Legacy Mode blocking. Ignored in Inline IPS mode. |
| Log to System Log | Leave unchecked | Copies Suricata messages to the pfSense system log. Useful for debugging but adds noise. |
| Keep Suricata Settings After Deinstall | ✓ | Preserves your configuration if you reinstall the package. Leave enabled. |
| Clear Blocked Hosts After Deinstall | ✓ | Clears any blocked IPs when removing the package. Leave enabled. |

### Notifications

| Setting | Value |
|---------|-------|
| Update | Leave unchecked unless you want email/Telegram alerts on rule updates |
| Rule Categories | Leave unchecked unless you want alerts when new rule categories appear |

> Notification delivery is configured under **System → Advanced → Notifications**.

Click **Save**.

## Step 2: Force Initial Rule Download

After saving Global Settings, force Suricata to download the rule sets immediately rather than waiting for the nightly cron job.

Navigate to **Services → Suricata → Updates**

You'll see the **Installed Rule Set MD5 Signatures** table listing each enabled rule set. Under **Update Your Rule Set**:

1. Click **Force**
2. Watch the log output — each rule set should download and show an MD5 hash and timestamp
3. If any rule set shows **failed**, check your Oinkmaster code (for Snort rules) or verify internet connectivity

> The Updates page also shows **Last Update** timestamp and result. If the result shows "failed" after a Force update, click **View** under Manage Rule Set Log to see the detailed error output.

## Step 3: Add Interfaces

Suricata monitors traffic per interface. You need to add each interface you want inspected.

Navigate to **Services → Suricata → Interfaces → + Add**

### Interface Settings (SERVE tab)

**General Settings**

| Setting | Value | Notes |
|---------|-------|-------|
| Enable | ✓ | Enables Suricata inspection on this interface |
| Interface | Select interface (e.g., `WAN (igb1)`) | Choose which interface this instance monitors |
| Description | e.g., `WAN` or `SERVERS_VLAN30` | For your reference — defaults to the pfSense interface description |

**Logging Settings**

| Setting | Value | Notes |
|---------|-------|-------|
| Send Alerts to System Log | Leave unchecked | Sends alerts to pfSense system log — adds significant noise |
| Enable Stats Collection | Leave unchecked | Periodically collects performance statistics |
| Enable HTTP Log | ✓ | Logs HTTP traffic. Useful for visibility into what's happening on your network |
| HTTP Log Type | Regular | Use Regular unless you need HEX or Stream Socket logging |
| Append HTTP Log | Leave unchecked | Appends rather than replaces the HTTP log on restart |
| Log Extended HTTP Info | Leave unchecked | Logs additional HTTP fields — enable if you're feeding logs to a SIEM like Wazuh |
| Enable TLS Log | Leave unchecked | Logs TLS handshake metadata. Not checked by default |
| Enable File-Store | Leave unchecked | Saves files extracted from application layer streams. **Warning:** Consumes significant disk space |
| Enable Packet Log | Leave unchecked | Logs packets in pcap format. Can consume a significant amount of disk space |
| Enable Verbose Logging | Leave unchecked | Adds additional info to the log on startup/shutdown |

**EVE Output Settings**

| Setting | Value | Notes |
|---------|-------|-------|
| EVE JSON Log | Leave unchecked | Outputs events in JSON format to a file or syslog. Enable if you're integrating with Wazuh or Elastic Stack |

**Alert and Block Settings**

| Setting | Value | Notes |
|---------|-------|-------|
| Block Offenders | ✓ | Automatically blocks hosts that trigger a Suricata alert. This is what enables IPS behavior |

**Performance and Detection Engine Settings**

| Setting | Value | Notes |
|---------|-------|-------|
| Run Mode | `AUTOFP` | Recommended for IDS-only and Legacy Blocking Mode. `Workers` is preferred for Inline IPS mode but requires more CPU. `Single` uses one thread for all operations. |
| AutoFP Scheduler Type | Hash | Controls how traffic flows are load-balanced across threads in AutoFP mode |
| Max Pending Packets | `1024` | Number of simultaneous packets the engine can handle. Minimum is 1, maximum is 65535. Setting too high can cause degradation. |
| Detect-Engine Profile | Medium | Recommended for most systems. Low uses less memory, High offers better performance at the cost of more memory. |
| Multi-Pattern Matcher Algorithm | Auto | Suricata will select the best algorithm. Auto defaults to Hyperscan if available. |
| Single-Pattern Matcher Algorithm | Auto | Same as above for single-pattern matching. |
| Signature Group Header MPM Context | Auto | Controls Suricata's multi-pattern context behavior. Auto selects between Full and Single based on the HFB algorithm. |
| Inspection Recursion Limit | `3000` | Error limit for recursive calls in content inspection. 0 means no limit. |
| Delayed Detect | Leave unchecked | Builds the list of signatures after packet capture threads start. Not checked by default. |
| Promiscuous Mode | ✓ | Places the monitored interface in promiscuous mode to capture all traffic, not just traffic addressed to it |
| Interface PCAP Snaplen | `1518` | Value in bytes for the PCAP adapter snaplen. Only valid when running in IDS or Legacy Mode IPS. |

**Networks Suricata Should Inspect and Protect**

| Setting | Value | Notes |
|---------|-------|-------|
| Home Net | default | Uses all local networks, WAN IPs, gateways, and VPNs by default. You can specify a custom alias here to limit what Suricata considers "home." |
| External Net | default | Everything that isn't Home Net. Leave as default. |

**Alert Suppression and Filtering**

| Setting | Value | Notes |
|---------|-------|-------|
| Alert Suppression and Filtering | default | Select the suppression or filtering list to apply to this interface. Assign your suppress list here after creating it (see Step 5). |

Click **Save**.

### Repeat for Each Interface

Add a separate Suricata instance for each interface you want monitored. Based on your setup:

| Interface | Recommended Blocking Mode | Notes |
|-----------|--------------------------|-------|
| WAN (igb1) | Inline IPS | Inspects all inbound/outbound internet traffic |
| LAN (igb0) | Legacy Mode | Inspects internal LAN traffic |
| DESKTOP_VLAN10 | Legacy Mode | Optional — add if you want per-VLAN visibility |
| SERVERS_VLAN30 | Legacy Mode | Recommended — servers are high-value targets |
| WIFI_VLAN20 | Legacy Mode | Optional |
| IOT_VLAN40 | Legacy Mode | Recommended — IoT devices are frequently targeted |

> **Inline IPS vs. Legacy Mode:** Inline IPS (shown on your WAN interface) is the more capable mode — it can drop packets mid-stream before they're processed. Legacy Mode works by blocking the source IP after a match is detected, which means the triggering packet gets through before the block takes effect. Inline IPS requires `Workers` run mode and is best suited for the WAN interface where you have the most exposure.

## Step 4: Pass Lists

Pass Lists tell Suricata which IP addresses should never be blocked, regardless of what rules they match. This is how you prevent Suricata from accidentally blocking pfSense itself, your ISP's DNS servers, or other trusted infrastructure.

Navigate to **Services → Suricata → Pass Lists → + Add**

**General Information**

| Field | Value |
|-------|-------|
| Name | e.g., `passlist_wan` |
| Description | Optional — for your reference |

**Auto-Generated IP Addresses**

Leave all of these checked (they are checked by default):

| Setting | Notes |
|---------|-------|
| Local Networks | Adds all locally-attached networks (excluding WAN) |
| WAN Gateways | Adds your ISP gateway IPs |
| WAN DNS Servers | Adds your WAN DNS server IPs |
| Virtual IP Networks | Adds any virtual IPs configured on pfSense |
| VPN Addresses | Adds any VPN tunnel addresses |

**Custom IP Addresses and Configured Firewall Aliases**

Add any additional IPs or pfSense alias names that should never be blocked. Enter IP addresses or alias names only — do not enter FQDNs directly. If you need to whitelist a domain, create a firewall alias for it first, then reference the alias name here.

Click **Save**, then assign the pass list to each interface under the interface's **Alert Suppression and Filtering** section.

## Step 5: Suppress Lists

Suppress Lists silence specific Suricata rule signatures without disabling them entirely. Use these when a rule is firing on legitimate traffic (false positives) but you don't want to turn the rule off globally.

Navigate to **Services → Suricata → Suppress → + Add**

**General Information**

| Field | Value |
|-------|-------|
| Name | e.g., `suppress_quic` |
| Description | Optional |

**Suppression List Content**

Enter suppression rules in the text box. Valid keywords are `suppress`, `event_filter`, and `threshold`.

```
# Suppress a specific rule entirely for a specific IP
suppress gen_id 1, sig_id 1852, track by_src, ip 10.1.1.54

# Rate-limit alerts from a specific rule (alert at most once per 60 seconds per source)
event_filter gen_id 1, sig_id 1851, type limit, track by_src, count 1, seconds 60

# Threshold — only alert after 100 occurrences per second
threshold gen_id 135, sig_id 1, type threshold, track by_src, count 100, seconds 1
```

Click **Save**, then assign the suppress list to each interface under the interface settings **Alert Suppression and Filtering** dropdown.

> **When to use suppress lists:** The most common use case in a home lab is suppressing QUIC protocol alerts (hence `suppress_quic`) — Chrome and other browsers aggressively use QUIC/UDP 443, which triggers a lot of noise in Suricata. Suppressing those lets you see the alerts that actually matter.

## Step 6: Start Suricata

Navigate to **Services → Suricata → Interfaces**

You'll see the Interface Settings Overview table listing each interface you configured with:
- **Suricata Status** — green check = running, red = stopped
- **Pattern Match** — AUTO by default
- **Blocking Mode** — Inline IPS or Legacy Mode

Use the play/stop buttons in the Actions column to start each interface instance. On first start, Suricata will compile all rules which can take a minute or two depending on how many rule sets you enabled.

## Verification

### Check Alerts

Navigate to **Services → Suricata → Alerts**

You should see alert entries appearing within a few minutes of starting Suricata. Each entry shows:
- Timestamp
- Interface
- Source/destination IP and port
- Rule SID and description
- Priority

### Check Blocks

Navigate to **Services → Suricata → Blocks**

Shows IPs that have been actively blocked. If Block Offenders is enabled and Suricata is matching rules, you should see entries here.

### Check Logs

Navigate to **Services → Suricata → Logs View**

Select an interface and log type to view raw Suricata output. Useful for debugging rule matches and understanding what's being detected.

## Tuning and Ongoing Maintenance

Suricata requires ongoing tuning, especially in the first few weeks. The goal is to reduce false positives until the alerts you see are meaningful signal rather than noise.

**Common false positive sources in home labs:**
- QUIC protocol traffic (Chrome, YouTube) — suppress with a suppress list
- BitTorrent detection on IoT or gaming VLANs
- DNS queries to public resolvers flagged by threat intel rules
- NTP traffic flagged by amplification rules

**Workflow for handling false positives:**

1. See an alert in **Alerts** tab
2. Research the SID — Google `suricata sid XXXXXX` to understand what the rule detects
3. If it's a legitimate false positive, add a suppression rule to your suppress list
4. If it's a real threat, investigate the source IP and consider adding it to a block list

**Monthly tasks:**
- Review **Blocks** tab and verify blocked IPs are actually malicious
- Check for Suricata package updates under **System → Package Manager → Installed Packages**
- Review suppress list — remove suppressions that are no longer needed

## Troubleshooting

**Suricata won't start**
- Check **Logs View** for error output
- Verify rules downloaded successfully under **Updates** tab
- Confirm the interface selected actually exists and is active in pfSense

**Too many false positives**
- Switch from IPS to IDS mode temporarily (uncheck Block Offenders) while tuning
- Build out your suppress list before re-enabling blocking
- Start with fewer rule sets and add more once things are stable

**Legitimate traffic being blocked**
- Check the **Blocks** tab for the source IP
- Click the X next to the IP to remove the block temporarily
- Add the IP or subnet to a Pass List to prevent future blocks
- If a specific rule is the culprit, add it to a Suppress List

**High CPU usage**
- Reduce the number of interfaces Suricata monitors
- Switch Run Mode from `Workers` to `AUTOFP`
- Disable rule categories you don't need under **SID Mgmt**
- Reduce Max Pending Packets

**Suricata and pfBlockerNG conflicts**
- pfBlockerNG and Suricata can both block the same traffic — this is fine and expected
- If you see unusual behavior, check **Firewall → Rules → Floating** to verify rule order
- pfBlockerNG rules should process before Suricata's inline rules
