# Setting up a Samba File Share on Ubuntu Server

**Author:** Greg Diny  
**Date:** November 15, 2025

A practical guide to setting up a local network file share using Samba on Ubuntu Server.

---

## Overview

This guide covers setting up a Samba file share on Ubuntu Server for local network file access. Samba implements the SMB (Server Message Block) protocol, which is what Windows uses for file sharing. This allows seamless file access from Windows, Mac, and Linux clients.

**Hardware Used:** Dell Wyse 5070 (Intel Celeron J4105, 8GB RAM, 256GB SSD)

---

## Prerequisites

- Fresh Ubuntu Server install
- User account created (e.g., `a_username`)
- Static IP configured (e.g., `your_ip_address`)
- Network access to the server

---

## Security Note

⚠️ **SMB uses port 445**, one of the most scanned ports on the internet. **Never expose this port to the internet.** Always include firewall rules to block port 445 from WAN access. Your pfSense WAN rules already block inbound traffic by default — the UFW rules below add a second layer of protection at the server itself.

## Installation Steps

### 1. Update System

```bash
sudo apt update
sudo apt upgrade -y
```

### 2. Install Samba

```bash
sudo apt install -y samba
```

Verify it's running:

```bash
systemctl status smbd --no-pager
```

You should see `active (running)`.

### 3. Create Shared Directory

```bash
# Create the share directory
sudo mkdir -p /srv/samba/shared

# Set ownership to your user
sudo chown -R file_manager:file_manager /srv/samba/shared

# Set permissions (2775 ensures new files inherit the group)
sudo chmod -R 2775 /srv/samba/shared
```

### 4. Add Samba User

Samba uses its own password database, separate from the Linux system login:

```bash
# Add user to Samba
sudo smbpasswd -a file_manager

# Enable the user
sudo smbpasswd -e file_manager
```

You'll be prompted to set the SMB password. This can be different from the Linux account password.

### 5. Configure Samba

Backup the default config first:

```bash
sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.bak
```

Edit the config:

```bash
sudo nano /etc/samba/smb.conf
```

Add this to the bottom of the file:

```ini
[shared]
    path = /srv/samba/shared
    browseable = yes
    writable = yes
    valid users = file_manager
    create mask = 0664
    directory mask = 2775
    force user = file_manager
    force group = file_manager
```

Save and exit (`Ctrl+X`, `Y`, `Enter`).

### 6. Test Configuration

```bash
testparm
```

This validates your Samba config and will report any syntax errors. Fix any errors before continuing.

### 7. Restart Samba

```bash
sudo systemctl restart smbd nmbd
sudo systemctl enable smbd nmbd
```

> `nmbd` handles NetBIOS name resolution, which allows clients to find the server by hostname instead of just IP address.

### 8. Configure Firewall (UFW)

Allow SMB access from each network segment that needs to reach the file share. Adjust the subnets to match your VLAN layout:

```bash
# Allow from Servers VLAN (local network where file server lives)
sudo ufw allow from 192.168.30.0/24 to any port 445
sudo ufw allow from 192.168.30.0/24 to any port 139

# Allow from Desktop VLAN
sudo ufw allow from 192.168.10.0/24 to any port 445
sudo ufw allow from 192.168.10.0/24 to any port 139

# Allow from WiFi VLAN
sudo ufw allow from 192.168.20.0/24 to any port 445
sudo ufw allow from 192.168.20.0/24 to any port 139

# Allow from IoT VLAN (only if IoT devices need file share access — most setups skip this)
# sudo ufw allow from 192.168.40.0/24 to any port 445
# sudo ufw allow from 192.168.40.0/24 to any port 139

# Enable firewall
sudo ufw enable

# Verify rules are in place
sudo ufw status
```

> **pfSense firewall rules also required:** Because your VLANs block RFC1918 traffic by default, you also need a pass rule in pfSense on each VLAN interface that allows TCP port 445 to the file server IP (`192.168.30.20`). Without this, traffic from your Desktop and WiFi VLANs will be dropped at the pfSense level before it even reaches the server. Add these under **Firewall → Rules → [VLAN interface]**:
>
> - Action: Pass / Protocol: TCP / Source: VLAN net / Destination: `192.168.30.20` / Port: 445
> - Action: Pass / Protocol: TCP / Source: VLAN net / Destination: `192.168.30.20` / Port: 139

## Connecting from Clients

### Windows

1. Open File Explorer
2. In the address bar type: `\\192.168.30.20\shared`
3. Enter credentials when prompted:
   - Username: `file_manager`
   - Password: (your Samba password)

To make the connection persistent, right-click the share in File Explorer and select **Map network drive**.

### macOS

1. Finder → Go → Connect to Server
2. Server address: `smb://192.168.30.20/shared`
3. Enter credentials when prompted

### Linux

```bash
# Install cifs-utils if not already installed
sudo apt install cifs-utils

# Create mount point
sudo mkdir -p /mnt/fileserver
```

**Manual mount (one-time):**

```bash
sudo mount -t cifs //192.168.30.20/shared /mnt/fileserver \
  -o username=file_manager,password=yourpassword,uid=$(id -u),gid=$(id -g)
```

**Auto-mount on boot via /etc/fstab:**

First, create a credentials file so your password isn't stored in plaintext in fstab:

```bash
sudo nano /etc/samba/credentials
```

Add the following:

```
username=file_manager
password=yourpassword
```

Lock down the credentials file so only root can read it:

```bash
sudo chmod 600 /etc/samba/credentials
sudo chown root:root /etc/samba/credentials
```

Then add this line to `/etc/fstab`:

```bash
sudo nano /etc/fstab
```

```
//192.168.30.20/shared  /mnt/fileserver  cifs  credentials=/etc/samba/credentials,uid=1000,gid=1000,iocharset=utf8,_netdev  0  0
```

> The `_netdev` option tells the system to wait for network connectivity before attempting to mount. Without it, the mount may fail on boot before the network interface is up. Replace `uid=1000` and `gid=1000` with your actual user and group IDs — run `id` to check.

Test the fstab entry without rebooting:

```bash
sudo mount -a
```

Verify it mounted correctly:

```bash
df -h | grep fileserver
```

## Troubleshooting

**Can't connect from Windows:**
- Verify UFW allows SMB from your client's subnet: `sudo ufw status`
- Verify pfSense has a pass rule for TCP 445 from your client's VLAN to `192.168.30.20`
- Check Windows network discovery is enabled (Control Panel → Network and Sharing Center)
- Try connecting by IP (`\\192.168.30.20\shared`) rather than hostname to rule out name resolution issues

**Permission denied:**
- Verify the user exists in Samba: `sudo pdbedit -L`
- Check directory permissions: `ls -la /srv/samba/shared`
- Confirm correct username and password — note the Samba password is separate from the Linux login password

**Service won't start:**
- Check config syntax: `testparm`
- Review logs: `sudo journalctl -u smbd -n 50`
- Verify port 445 isn't already in use: `sudo ss -tulpn | grep 445`

**fstab auto-mount fails on boot:**
- Confirm `_netdev` is in the fstab options
- Check the credentials file path is correct and permissions are `600`
- Test manually with `sudo mount -a` and review any error output
- Check logs: `sudo journalctl -b | grep cifs`

## Security Best Practices

1. ✅ Never expose port 445 to the internet
2. ✅ Use strong Samba passwords
3. ✅ Restrict access with `valid users` in smb.conf
4. ✅ Use UFW to limit access to specific VLANs only
5. ✅ Add pfSense pass rules only for VLANs that genuinely need file share access
6. ✅ Store fstab credentials in a root-owned `600` credentials file, never in plaintext in fstab
7. ✅ Use VPN for remote access rather than port forwarding
8. ✅ Keep the system updated: `sudo apt update && sudo apt upgrade`
